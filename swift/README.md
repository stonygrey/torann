# Torann for Swift

Torann is a Swift implementation of the Noise Protocol Framework, revision 34, for iOS 18 and later and macOS 15 and later. The repository README at https://github.com/stonygrey/torann explains Noise and describes how the API is used, and `readme/torann-api.md` specifies the API that every Torann package shares. The package manifest is `Package.swift` at the repository root, because SwiftPM reads it from there. The sources are in `swift/Sources/Torann` and the tests in `swift/Tests/TorannTests`.

## Functions

The Diffie-Hellman function is `25519`, the ciphers are `ChaChaPoly` and `AESGCM`, and the hashes are `SHA256` and `SHA512`. A protocol name that asks for `448`, `BLAKE2s`, or `BLAKE2b` fails at parse time with `TorannError.unsupportedFunction`, because CryptoKit, Apple's cryptography framework, provides none of those functions and the package takes no dependencies. The shared vectors in `vectors/` contain 440 protocol and key combinations for this function set, and `swift test` runs all 440.

## Installation

Add the package by its repository URL. SwiftPM reads the version from the repository's git tags, which every Torann package shares.

```swift
.package(url: "https://github.com/stonygrey/torann.git", from: "0.3.0")
// and in the target:
.product(name: "Torann", package: "torann")
```

## Usage

```swift
import Torann

let proto = try NoiseProtocol.parse("Noise_XX_25519_ChaChaPoly_SHA256")
let staticKey = try proto.generateKeyPair()          // store try staticKey.privateKey for reuse
let handshake = try proto.createHandshake(initiator: true, localStatic: staticKey)

let first = try handshake.writeMessage()             // send first.message
// let reply = try handshake.readMessage(received)
// ... the final message's result carries handshakeHash and transport
// let ciphertext = try transport.writeMessage(payload: data)
// let plaintext = try transport.readMessage(ciphertext)
```

Errors are the cases of `enum TorannError`, one per category, each carrying its message except `closed`. `KeyPair`, `HandshakeState`, and `Transport` are `Sendable`, and every operation runs under a `Mutex` inside the object. After `close()` every operation throws `TorannError.closed`.

## Crypto

Every primitive comes from CryptoKit: `Curve25519.KeyAgreement` for X25519, `ChaChaPoly` and `AES.GCM` for the AEAD ciphers, and `SHA256`, `SHA512`, and `HMAC` for hashing.

CryptoKit rejects low-order X25519 public keys: `sharedSecretFromKeyAgreement` throws for the point at infinity and for the other six low-order points, and the library turns that into `TorannError.authenticationFailed("The peer's public key is invalid.")`.

Key hygiene is limited in three ways. First, CryptoKit holds its own copies of every secret. A `SymmetricKey` and a `Curve25519.KeyAgreement.PrivateKey` are opaque values with no wipe operation, so the library can only drop its references to them. The same holds for the `SharedSecret` of each Diffie-Hellman operation, for the `SymmetricKey` built from the chaining key for every HMAC, and for the `HashedAuthenticationCode` that `HMAC.finalize()` returns for every HKDF output. Second, Swift arrays are copy-on-write values. The library zeros the `[UInt8]` buffers it owns with `memset_s`, but a `Data` or `[UInt8]` value returned to the caller is the caller's own copy, and the library does not reach it. Third, the Swift runtime may leave copies of a value in registers, on the stack, or in the old storage of a reallocated array, and the library makes no attempt to scrub those.

Ephemeral and static keys are generated by `Curve25519.KeyAgreement.PrivateKey()`, which uses the system's cryptographic random number generator. A private key supplied through `createKeyPair(privateKey:)` is used as given. CryptoKit clamps the scalar inside the operation and returns the stored bytes unchanged, so a private key generated by another Torann implementation derives the same public key here.

## Tests

`swift test` runs the vectors, the security tests, and the RFC 7748 §6.1 key derivation and shared secret example on macOS. The command `xcodebuild test -scheme Torann-Package -destination 'platform=iOS Simulator,name=iPhone 16,OS=18.6'` runs them on the iOS Simulator at the minimum supported version. The Simulator runs the test process on the host, so it reads the vector files from the host file system. The test-only entry point that sets a fixed ephemeral key is an internal method reached with `@testable import Torann`.
